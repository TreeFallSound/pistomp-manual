# Wah Plugin Research: Cry Baby Replacements on pistomp

## Summary of findings

The Guitarix LV2 wah family is built on **two distinct DSP cores**, both derived from **SPICE-level analog circuit simulation** of real wah pedals (the `holters-sim/crybaby-1.2` circuit simulator, curve-fit to 4th-order IIR coefficients by `trunk/tools/dunwah1.py` / `dunwah2.py`). This is genuine analog inductor/capacitor modelling, not arbitrary biquads — the polynomial coefficients in `dunwahauto.cc:run()` (`1973.48 - 1000/poly(wah)` for frequency, polynomial in `wah` for Q) are least-squares fits to the impulse response of a simulated Cry Baby circuit at multiple treadle positions.

There are **two Cry Baby models** in the tree, both SPICE-fit:

1. **`dunwah` / `dunwahauto`** (in `gxautowah.lv2`, hand-written C++ in `dunwahauto.cc`) — derived by `dunwah2.py` from the `holters-sim/crybaby-1.2` simulator. Sweep **413 Hz (heel) → 2184 Hz (toe)**, Q **22 (heel) → 3.0 (toe)**. This matches the real GCB-95: heavy low-end resonance that thins out at the toe. The `gxautowah.lv2` bundle exposes **two plugins** sharing this core:
   - `GxWah` (URI `…#wah`) — manual treadle, controlled by the `fslider1_`/WAH port. **This is the plugin the device lists as `gxwah.lv2`.**
   - `GxAutoWah` (URI `…#autowah`) — the **switchless** variant: an envelope follower (`fabs(input)` smoothed with a ~10 s attack/decay pole, `fConst1 = exp(-10/SR)`) drives the `wah` parameter automatically from playing dynamics. **This is the plugin the device lists as `GxSwitchlessWah.lv2`.** Auto-engagement is confirmed: there is no bypass/footswitch port beyond `BYPASS`; the filter sweep is driven by `fRec2[0] = fTemp0` (envelope) fed straight into the same polynomial coefficient generator as the manual version (`gxautowah.cpp:80` dispatches `#autowah` → `crybaby::run` = `dunwahauto::run`).

2. **`gx_gcb_95.lv2`** (Faust-generated from `gcb_95.dsp`, which is produced by `build_GCB_95.py`) — a **separate, more detailed 4th-order IIR** model of the GCB-95 with the treadle mapped through an inverted log pot (`LogPot(5)`, matching the Hot Potz taper) and a **228 Hz DC-blocker pre-stage** matching the Cry Baby's input C-R coupling. Ports: `HOTPOTZ` (treadle, 0–1, default 0.5) + `VOLUME`. This is the most literal "GCB-95" model — its `.dsp` header literally says *"Linear filter simulating the GCB 95 ve.crybaby circuit."* Sweep range is comparable to `dunwah` (heel ~400 Hz, toe ~2 kHz+).

The **`gx_colwah.lv2`** ("GxWahwah") is a **7-model wah switcher** (`gx_colwah.cpp:41-48`): Colorsound / Dallas Arbiter / Foxx / Jen / Maestro / Selmer / Vox V847. Each model is its own SPICE-fit 4th-order IIR (`dallaswah.dsp`, `voxwah.dsp`, etc.). **None of these seven is a Cry Baby/Dunlop** — the Cry Baby is a different topology (the inductor is tapped differently) and lives in the separate `gx_gcb_95`/`gxautowah` plugins. The Color Wah is a multi-pedal chameleon, not a Cry Baby stand-in, though the Vox V847 model (MODEL=6) is tonally adjacent (Vox/Dunlop share lineage). It offers manual / auto (envelope) / alien (LFO) modes via the `MODE` port.

**`gx_quack`** does **not exist** in the Guitarix source tree (verified via `rg -i quack` across the full repo and `git log -S quack` — zero hits) nor in ZynAddSubFX. It is not a Guitarix plugin. It likely comes from a different LV2 set installed on the device (e.g. `caps` or a MOD port), or is a misremembered/alias name. **Its DSP could not be inspected**; treat any "quack" plugin on the device as unverified topology and audition it manually. Given the name, it *may* be a sharper-Q/envelope-wah variant, but that is speculation — do not assume it is a Cry Baby model.

**`ZynAlienWah.lv2`** is **not a wah at all** — its own LV2 metadata declares `DISTRHO_PLUGIN_LV2_CATEGORY "lv2:PhaserPlugin"`. The DSP (`Alienwah.cpp:out()`) is a **complex-modulated feedback delay line**: an LFO generates a rotating complex coefficient `cos(φ)·fb + j·sin(φ)·fb` that multiplies a delayed sample (`oldl[oldk]`), summed with `(1-|fb|)·input`. This is a sweepable comb/phase-shifter with feedback — a **phaser**, not a resonant bandpass. No inductor, no bandpass peak, no treadle. It will not sound like a Cry Baby; it sounds like a metallic auto-sweep.

## Ranking as a faithful Cry Baby (GCB-95 / JH-1) stand-in

**1. `gx_gcb_95.lv2` — best, most literal.** It is the direct, named GCB-95 circuit model: SPICE-fit 4th-order IIR, Hot Potz taper (inverted log), 228 Hz input DC-blocker matching the real pedal's coupling network, and a `HOTPOTZ` treadle port (0–1) plus output volume. Of all candidates it is the one whose DSP was generated specifically to emulate the GCB-95. Drive the `HOTPOTZ` port from an expression pedal and it behaves like a Cry Baby. Use this for the Joseph D'Agostino treadle-sweep sound.

**2. `gxwah.lv2` (GxWah, URI `…#wah`) — excellent, same Cry Baby core, manual.** Shares the SPICE-fit Cry Baby filter from `dunwahauto.cc` (413 Hz→2184 Hz, Q 22→3). It is the manual-treadle sibling of the autowah. Functionally a Cry Baby with a slightly different coefficient fit than `gx_gcb_95` (from `dunwah2.py` vs `build_GCB_95.py` — same simulator, different fit order). Audibly near-identical to #1; rank it essentially tied. Choose this if you want the GxAutoWah bundle's manual wah and don't need the Hot Potz volume trim.

**3. `GxSwitchlessWah.lv2` (GxAutoWah, URI `…#autowah`) — same Cry Baby core, auto-engaged.** Identical filter to #2, but the treadle is driven by an envelope follower (attack/decay pole ≈ `exp(-10/SR)`, i.e. a slow ~10 s envelope time constant) gated by a sensitivity/depth control. Auto-engagement is confirmed in code: no footswitch, sweep = `fRec2[0]` (envelope) → polynomial coeffs → same 4th-order IIR. This is the right pick if you want Cry Baby tone *without* an expression pedal — the wah opens on dynamics and closes when you stop playing. Sonically a faithful Cry Baby; behaviour is auto-wah, not classic treadle. For D'Agostino's manually-swept parts, #1 or #2 is more authentic; for hands-free wah textures this is ideal.

**4. `gx_colwah.lv2` (GxWahwah) — Cry Baby-adjacent only via its Vox V847 model.** A 7-model switcher of *other* vintage wahs (Colorsound, Dallas, Foxx, Jen, Maestro, Selmer, Vox V847). All are SPICE-fit 4th-order IIRs (good quality), but **none is a Cry Baby** — the Cry Baby/Dunlop inductor topology is absent. MODEL=6 (Vox V847) is the closest tonal cousin since Vox and Dunlop share ancestry, and you get manual/auto/LFO modes plus a wet/dry blend. A fine and flexible wah, but not a faithful GCB-95 — it's a "different pedal" emulator. Use it when you want wah *character* rather than Cry Baby specifically.

**5. `ZynAlienWah.lv2` — not a wah; do not use as a Cry Baby substitute.** It is a phaser (self-declared `lv2:PhaserPlugin`): LFO-modulated complex feedback delay, sweepable comb filtering. No bandpass resonance, no inductor model, no treadle. Will sound metallic/phasey, nothing like a Cry Baby's vocal peak. Excluded from Cry Baby consideration.

**6. `gx_quack.lv2` — unverified / source not found.** Not present in Guitarix or ZynAddSubFX source. I could not inspect its DSP, so I cannot rank it. If it exists on the device it comes from another plugin set; audition it manually and check its TTL (`lv2:symbol`, port ranges) before trusting it. By name it *suggests* a sharper, more vocal/aggressive envelope wah, but that is speculation — do not assume it is a Cry Baby model.

## Bottom line
For a faithful Dunlop Cry Baby stand-in on pistomp, use **`gx_gcb_95.lv2`** (most literal, with Hot Potz taper + volume trim) or **`gxwah.lv2`** (same Cry Baby core, manual). Add **`GxSwitchlessWah.lv2`** when you want the same tone hands-free. Ignore `ZynAlienWah`; treat `gx_colwah` as a different-pedal emulator; and verify `gx_quack`'s actual source before relying on it.
