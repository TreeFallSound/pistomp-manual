# DD-3 Replacement Report

The Boss DD-3 is a clean, full-bandwidth integer-sample digital delay: no interpolation needed (delay time is fixed, not modulated), no feedback filtering, no modulation, up to 800 ms. The closest LV2 match is the one with a transparent feedback path, integer reads, and enough delay time — **`tap-echo.lv2`**, with `ZamDelay` and `distrho-a-delay` tied just behind (once their default LPF is opened up).

## Ranking

### 1. `tap-echo.lv2` — TAP Echo (Tom Szilagyi) — best match
The cleanest and most DD-3-like of the five. Stereo (separate L/R delay, feedback, and strength controls), max delay **2000 ms** (covers DD-3's 800 ms with headroom). The delay line in `tap_echo.c:289-323` is a pure integer-sample ringbuffer (`push_buffer` in `tap_utils.h:36` just writes one float and returns the oldest — no interpolation, no fractional reads). The feedback path is a single scalar (`feedback_L/R`), and the output is `dry*drylevel + delayed*strength` — **no filtering in the feedback path and no output tone control**. There is no modulation, no tape wow, no bitcrush. The only extras are routing conveniences (Haas blank, mode cross-routing, output-channel reverse) that are inert when left at defaults. This is the only candidate whose default signal path is uncoloured end-to-end, exactly like a DD-3. Downside: it is stereo-only, so for a mono pedalboard you simply feed both channels the same signal and link L/R. Code is simple and correct, with parameter smoothing on strength/dry (`tap_echo.c:266-273`).

### 2. `ZamDelay.lv2` — Zam Delay (Damien Zammit) — close, with one knob to set
Mono in/out, max delay **8000 ms**. Integer-sample delay line (`ZamDelayPlugin.cpp:358-360` reads `z[p]`), with a two-tap crossfade on delay-time changes (`recalc` block, lines 362-368) that makes delay-time edits glitch-free — a nicety the DD-3 lacks but never harmful. Feedback path is a transparent scalar (`feedb * fbstate`, line 356) — no filtering in the loop. The one catch: an RBJ low-pass on the **wet output** (`runfilter`, default `lpf = 6000 Hz`, line 139) colours the repeats; set **LPF to 20000** to make it transparent and you have a clean digital delay that is functionally DD-3-equivalent. Has an invert (phase-flip) toggle and BPM sync. Code is clean and well-structured (DPF-based).

### 3. `distrho-a-delay.lv2` — DISTRHO a-delay (Robin Gareus / Damien Zammit) — tied with ZamDelay
Architecturally near-identical to ZamDelay (same author lineage): mono, integer-sample delay (`a-delay.c:473-475`), two-tap crossfade on recalc (lines 477-483), transparent scalar feedback (line 472), and the same RBJ LPF on the wet output defaulting to 6000 Hz (line 138 — open it to 20000 for flat response). Max delay **8 s @ 96 kHz** (`MAX_DELAY 768000`, line 33). Adds BPM sync via atom TimePosition, dotted, and invert. Same rank as ZamDelay; pick whichever UI/parameter set fits the pedalboard better. Slightly older code style (raw LV2 C rather than DPF) but correct, with denormal guards.

### 4. `gx_digital_delay.lv2` — Guitarix Digital Delay — capable but not neutral by default
Faust-generated, mono in/out, max delay **5000 ms**. Uses `de.sdelay` — Faust's **linear-interpolated** smooth delay (visible in `digital_delay.cc:389`: `(1-fRec29)*sample_at_low_tap + fRec29*sample_at_high_tap`). Linear interpolation is cleaner than integer reads when delay time is being swept, but the DD-3 never sweeps, so this is a wash for the use case — and linear interpolation slightly softens HF on every repeat versus a pure integer read. The decisive drawback versus the top three: the feedback path **always** runs through `fi.highpass(2, HIGHPASS) : fi.lowpass(2, HOWPASS)` (`digital_delay.dsp:36`), with defaults HP=120 Hz / LP=12 kHz. You can widen this to 20 Hz / 20 kHz to approach full bandwidth, but the filters are never bypassable, and the LP at 20 kHz on a 48 kHz host still rolls off the top octave of every repeat. The MODE enum offers plain / presence / tape / tape2; only **plain (0)** is DD-3-appropriate — presence adds a multi-peak guitar EQ, and tape/tape2 insert allpass chains (`digital_delay.dsp:11-12`) that emulate tape wow/flutter colouration. Also has a Freeze (hold) toggle, matching the DD-3's hold on the 800 ms setting. Most featureful, but the always-on feedback filtering and the easy-to-accidentally-enable tape modes make it a poorer *default* DD-3 substitute than the three above.

### 5. `mod-mda-Delay.lv2` — MDA Delay — clean but too short
Stereo, integer-sample delay (`mdaDelay.cpp:256-257`, `*(buffer + l)`), no modulation, no tape. The dealbreakers for a DD-3 substitute: **max delay time is only ~330 ms** (`mdaDelay.cpp:92`, `ldel = getSampleRate()*0.33*fParam0`, clamped by a fixed 32766-sample buffer at line 40) — well short of the DD-3's 800 ms mode — and the feedback path **always** passes through a one-pole low-pass with a "Fb Tone" knob that crossfades between low-passed and high-passed feedback (`mdaDelay.cpp:118-128`, applied at lines 260-261). There is no flat-feedback setting; the tone control is always in the loop. Fine for the kind of coloured tape-ish delay MDA aimed for, wrong tool for pristine DD-3 repeats.

## Recommendation
Use **`tap-echo.lv2`** as the default DD-3 replacement — it is the only one whose signal path is transparent by default (no LPF to remember to open, no tape mode to avoid). If you need a mono instance with BPM sync, **`ZamDelay`** with LPF=20000 is equally clean and a perfectly good substitute; `distrho-a-delay` is the same plugin with a fancier UI. Avoid `mod-mda-Delay` for this role (delay time too short, feedback tone always coloured), and treat `gx_digital_delay` as a "delay Swiss-army knife" rather than a DD-3 stand-in (always-on feedback filtering, tape modes one click away).
