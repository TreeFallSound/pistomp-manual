# TS9 / TS10 Stacked-Boost Replacement — LV2 Plugin Analysis

### Methodology
Cloned the Guitarix core repo (`gxts9.lv2` DSP + Faust source `ts9sim.dsp` + table generator `tools/ts9sim.py`) and three separate brummer10 LV2 repos (`GxSD1.lv2`, `GxOverDriver.lv2`, `GxClubDrive.lv2`). Read the Faust source, the generated C++ DSP, and the nonlinearity lookup tables. Computed filter corners from component values declared in the DSP.

### Ranking (best → worst as a stacked midrange boost for fuzz)

**1. `gxts9.lv2` — GxTubeScreamer (the clear winner)**
This is a faithful, SPICE-derived model of the actual TS-9, not a generic waveshaper. The Faust source (`src/plugins/ts9sim.dsp`) is explicitly *"based on a circuit diagram of the Ibanez TS-9 and a mathematical analysis published by Tamás Kenéz"*. The signal chain is the real TS-9 topology: a pre-clip high-pass `tf1` with `R1=4700 Ω`, `C=0.047 µF` → **fc = 720.5 Hz** (I computed this from the declared values — this is *exactly* the Tube Screamer mid-hump frequency, the whole reason the pedal cuts bass and boosts mids before the clipper), feeding `ts9 = _ <: _ - ts9nonlin(X2-_) :> _` — i.e. the input minus a nonlinear function of the high-passed signal, which is the **op-amp feedback-loop clipper** (soft, symmetric, in the loop — not a hard shunt to ground). The `ts9nonlin` table is generated by `tools/ts9sim.py`, which solves the actual diode equation `Is·(exp(D/mUt) − exp(−D/mUt))` with `Is=10 pA`, `mUt=30 mV` via `scipy.optimize.brentq` against `R2 = 51 kΩ + 500 kΩ·drive` — that's the TS-9's gain pot with the real diode pair in the feedback path. The table is symmetric (odd, via `copysign`), matching the TS-9's antiparallel diode pair. Tone control is a 1-pole low-pass (`fi.lowpass(1, fc)`, default 400 Hz, range 100–1000 Hz) — the active tone stack's high-cut. Level is a smoothed dB gain (default −16 dB, range −20 to +4). This plugin hits every Tube Screamer signature: op-amp feedback soft clip, 720 Hz pre-clip HPF (the mid-hump), post-clip tone LPF, correct drive taper. **This is the authentic choice and the correct boost to stack before a fuzz for D'Agostino's mid-push technique.** Set Drive low (~0.2–0.3), Level to unity-ish, Tone ~400 Hz.

**2. `gx_sd1sim.lv2` — GxSD1 / "Super Overdrive" (close cousin, one important caveat)**
Boss SD-1 is a TS-9 derivative, and the code reflects that — it's the same architecture: pre-clip high-pass (reuses the exact `9.4e-8·SR` coefficient = the 720 Hz HPF), op-amp feedback clipper via `sd1nonlin((fRec3[0] - fTemp1))`, post-clip 1-pole tone LPF (same `fConst9 = 0.0004418·SR` coefficient as TS-9), smoothed dB level. The `sd1table` was generated by the same `ts9sim.py` solver (same `xf(x)=x/(3+x)` companding, same diode equation). **Two real differences from TS-9:** (a) drive taper is *exponential* (`4.75e-5·(exp(5·drive)−1)`) vs TS-9's linear `500000·drive+55700` — the SD-1 pot sweep feels faster; (b) there's an *extra* second-order pre-clip filter section (`fConst2..7`, coefficients `2.08e-5·SR` and `2.02e-5·SR` → ~80 Hz HPF + a shelf) the TS-9 doesn't have, modelling the SD-1's extra input coupling network. **The critical caveat:** a real Boss SD-1's defining feature is *asymmetric* clipping (one extra diode in one direction → even harmonics, "harder" feel). This model's `sd1nonlin` uses `copysign(f, -x)` — the same odd-symmetric table form as TS-9. **The diode asymmetry is NOT modeled.** So this is effectively a TS-9 with a different drive taper and a slightly different input filter — sonically very close to `gxts9`, slightly more aggressive gain sweep. Fine as a stacked boost, but it's mis-named: it won't give you the real SD-1's asymmetric even-harmonic character. Use it if you want a TS-9 with a faster drive knob; otherwise prefer the real `gxts9`.

**3. `gx_overdriver.lv2` — GxOverDriver (not a Tube Screamer; a generic waveshaper)**
Not TS-family. No op-amp feedback loop, no 720 Hz pre-clip HPF, no Kenéz/TS-9 lineage. The DSP (`overdriver.cc`, generated from `overdriver.dsp`) is a **two-band split filter** (a pair of 2nd-order recursive filters, `fRec1`/`fRec2`, whose coefficients `fConst1..17` are fixed polynomial expansions of `SR` — not derived from any named pedal's component values) followed by a **fixed lookup-table waveshaper** (`ftbl0[100]`, filled once at `init()` from `SIG0::fWave0`, a hardcoded symmetric saturating curve going 0→2.096) applied to the filtered sum. The nonlinearity is `fTemp6/(3+fTemp6)`-companded then table-lookup — the *same* companding trick as TS-9's `xf`, but the table is a hand-set static curve, **not solved from a diode equation**, and the clipping is **feed-forward** (waveshaper after the filter), **not feedback-loop**. Controls are LEVEL, TONE (a mix between the two fixed filter bands, 0–1), VOLUME — no DRIVE pot; "drive" is baked into the table's fixed threshold. There's no mid-hump: the filter bands are fixed, not centred at 720 Hz, and there's no active tone stack. This is a cheap-ish "overdrive flavour" DSP, not an analog-circuit model. **Not recommended as a TS stacked-boost** — it lacks the mid-hump pre-emphasis and the feedback-clip character that makes a Tube Screamer tighten a fuzz.

**4. `gx_clubdrive.lv2` — GxClubDrive (not TS-family at all; EF86 pentode preamp)**
The README states it outright: *"Overdrive Pedal Simulation based on a EF86 Pentode Valve Simulation."* This is a **pentode tube preamp model**, not a Tube Screamer and not a Blues Driver / Klon derivative. The DSP (`clubdrive.cc`, Faust 2.15.11 generated) is heavyweight: it **upsamples to 96 kHz** via `gx_resample::FixedRateResampler` (the only one of the four that resamples), then runs a 5th-order preamp filter (`fRec6[5]`) with drive-dependent coefficients (`fRec7` = exp drive, `0.000367·(exp(3·drive)−1)`) into a **pair of asymmetric pentode transfer tables** — `clubman_p2clip` for positive signal and `clubman_p2_negclip` for negative, with *different* table bounds (positive: `sig_max=1.4, div=64.4`; negative: `sig_max=−1.4, div=44.1`) — so this *is* genuinely asymmetric, but it's modelling a pentode's grid, not a pair of silicon diodes. After the clipper there's a 7-tap output filter (`fRec5[7]`) and a 2nd-order tone/volume network (`fRec4`, `fRec3`) — but **no 720 Hz mid-hump, no TS-style active tone stack, no feedback-loop diode clipper.** Controls are DRIVE, VOLUME, and a V1 bargraph (output meter) — no TONE control at all. It also has a 4096-sample attack hold (`iRec1`) for a peak-hold gain envelope. Code quality is high (oversampled, separate half-wave tables, polynomial-fitted filter coefficients) but it's modelling the wrong circuit entirely. **Reject for this use case** — it'll colour the fuzz differently (pentode compression + asymmetric soft clip) and has no mid-hump to push the fuzz into the D'Agostino frequency pocket.

### Recommendation
Use **`gxts9.lv2`** as the stacked boost. It is the only one of the four that is a genuine SPICE/diode-equation-solved model of the actual TS-9 circuit, with the verified 720 Hz pre-clip high-pass and feedback-loop symmetric soft clip. Set Drive ~0.25, Level near unity, Tone ~400 Hz, place it *before* the fuzz in the MOD-Host chain. If you want a slightly faster gain sweep, `gx_sd1sim.lv2` is a near-equivalent fallback — but be aware its "SD-1 asymmetry" is cosmetic; the diode clipper is symmetric like the TS-9, so you're not actually getting the SD-1's even-harmonic character. Skip `gx_overdriver` (feed-forward waveshaper, no mid-hump) and `gx_clubdrive` (EF86 pentode preamp, wrong circuit family) for this role.
